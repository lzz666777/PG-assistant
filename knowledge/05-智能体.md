# 智能体：预测助手

## 定位
智能体只做三件事：把自然语言变成查询、调用预测／仿真工具、把结果讲清楚。它不直接“拍脑袋给方案”，定位是“预测助手”，不是“调度大脑”。

## 工具设计
- query_station：查站点属性、历史占用、价格。
- forecast_queue：预测未来 1—3 小时等待时间分布。
- rank_alternatives：按等待、绕行、价格排序候选站。
- simulate：跑引导／扩容情景，返回 KPI 对比。
- explain：解释“为什么这个站堵、为什么推荐这个站”。

## 示例
用户：“明天 8 点从五一广场出发，电量 30%，去哪充？”
智能体：先 forecast_queue 预测周边站等待 → rank_alternatives 排序 → 给推荐＋理由＋地图高亮 → 说明不确定性。

用户：“这个站要不要扩容？”
智能体：查历史排队与需求 → 算边际收益 → 给“先扩／再等等”的建议和依据。

## 防幻觉
- 只基于工具返回的数据回答；工具没返回就说“查不到”。
- 显示时间戳、样本量、不确定性。
- 不编站点、不编价格、不编政策。
- 回答带“依据”链接或来源标注。

## 实现
- LLM function calling（DeepSeek／OpenAI 兼容接口）。
- 工具用 Python／FastAPI 封装，返回 JSON。
- 前端把工具调用过程可视化（“正在查 3 个站……”）。
- 先做 3 个工具（query／forecast／rank），跑通再加 simulate／explain。
